# 合成 brief C · 三支柱全开型

> 用途：专打三支柱。A/B 两份只要有一柱缺失就可能「看起来还行」，这一份的存在意义
> 是让三支柱的缺失在验收阶段**立刻**现形，而不是等真跑几周后才发现团队没记忆、没板。

## 一、自然语言 brief

> 给我一支小型行业监测队：一个盯梢岗每天扫源出增量，一个分析岗每周出趋势并押注，
> 一个投稿岗把结论落成板。三个岗位各自的记忆要分开——盯梢记「哪些源空了」，
> 分析记「哪些押注到期对上了」，投稿记「哪块板用了哪版数据」。

## 二、期望发布对象的形状

| 段 | 期望 |
|---|---|
| `memory` | 四轴齐；**三岗 `guidance` 语义互不重叠**（源侧 / 判断侧 / 产物侧） |
| `memory.store.home` | `member`（三岗各自分区，不共库） |
| `toolkit` | 三岗工具面**互不相同**：盯梢只读源、分析可读结果、投稿持落板面（无 publish） |
| `dashboard` | 板骨架 + 三岗投稿面接线，明确「哪一岗哪一轮产出哪一列」 |
| `acceptance` | ≥7 条；三支柱**各至少 2 条**（一条结构、一条判据） |
| `evidence` | 首版可为空；升版必须带三项 |

## 三、坏设计清单

1. **三岗 `guidance` 写成同一句** → memory 断言判红（可分辨性检查）。
2. **三岗工具面写成完全一样** → toolkit 断言判红（收窄失效＝等于没收窄）。
3. **看板只写骨架不写接线人** → dashboard 断言判红（板存在但没人投稿，等于空板）。
4. **`memory.store.home` 写成 `fleet`** → 不判红但语义降级（三岗共库），
   必须在报告里标「与 brief 的三岗分离要求不符」（记为告警）。
5. **投稿岗持有 publish** → 写面禁令判红。
