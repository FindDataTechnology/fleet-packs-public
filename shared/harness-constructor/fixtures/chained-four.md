# 合成 brief B · 四岗链式编导型

> 用途：验证编导边与错峰。这是元线配置与其它舰队最容易写错的一类形状——
> 四个岗位靠 handoff 串起来，任一环缺席整条链就断，但报数仍可能「看起来正常」。

## 一、自然语言 brief

> 做一条跨境电商合规的活：先扫政策与海关公告，再把可疑项按要素拆开（主体/商品/金额/流向），
> 然后逐条判定要不要升级，最后汇总成日报并出板。每天一轮，四步要错开，别挤在一起。

## 二、期望发布对象的形状

| 段 | 期望 |
|---|---|
| `manifest.agents` | 4 岗：扫描 / 拆要素 / 定级 / 汇总 |
| `org` | 4 个 member，`parentRef` 成链（汇总 ← 定级 ← 拆要素 ← 扫描） |
| `org.orchestration.edges` | ≥3 条 handoff（沿链）+ 1 条 cron trigger |
| `toolkit` | 每岗工具面按该岗动作收窄（定级岗可含确认门相关只读，**不含** publish） |
| `memory` | 四轴齐；四岗 `guidance` 各不相同（不能四岗抄同一句） |
| `dashboard` | 一块板 + 逐岗投稿面接线（谁产哪一列要写清） |
| `acceptance` | ≥6 条；含 `escalate-bounded`（升级项有上限） |
| cadence | 相邻岗位间隔 ≥30 分钟 |

## 三、坏设计清单

1. **断链**：删掉「拆要素 → 定级」这条 handoff → 链断但 `post-materialized` 仍绿；
   必须由「四岗各自 `first-round-fired`」或链条断言判红（**这正是纯 post 断言的盲区**）。
2. **四岗同一分钟**：全部 `30 9 * * *` → 节奏错峰断言判红（同 cell 串行队列会互相挤）。
3. **定级岗没报数**：只跑不报 → `report-landed` 针对该岗判红。
4. **升级无上限**：`escalate-bounded.expect` 缺省成 0 但实际每轮都升级 → 判红。
5. **四岗 guidance 抄同一句** → memory 支柱断言判红（章程必须逐岗可分辨）。
